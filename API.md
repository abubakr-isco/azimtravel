# API сервера для Azim Travel CRM

CRM — статический сайт (`index.html`, `css/`, `js/`). Серверу нужно отдать эти файлы и реализовать **один адрес** `/state`, где хранится вся база CRM одним JSON-документом с номером версии.

Адрес API задаётся в `js/config.js` (`api: "/api"`) или при сборке: `python3 tools/build.py --api /api`. Дальше в примерах `api = /api`.

## GET /api/state — получить базу

Ответ `200`:

```json
{ "rev": "17", "data": { "requests": [...], "vehicles": [...], "settings": {...}, "seq": 248, ... } }
```

- `rev` — версия базы, любая строка или число; меняется при каждом сохранении.
- `data` — база целиком, как её прислала CRM. Сервер её не разбирает и хранит как есть.
- Если базы ещё нет: `{ "rev": null, "data": null }` (или ответ `404`). CRM сама отправит первые данные: то, что было в браузере, или данные из Excel (`js/data.js`).

CRM раз в 30 секунд и при возврате на вкладку спрашивает `GET /api/state?rev=17`, чтобы подтянуть правки других сотрудников. Если версия не изменилась, можно ответить коротко: `{ "rev": "17", "unchanged": true }`. Можно и всегда отдавать полный ответ, это тоже работает.

## PUT /api/state — сохранить базу

Тело запроса (`Content-Type: application/json`):

```json
{ "rev": "17", "data": { ... } }
```

`rev` — версия, на основе которой сделаны правки (`null`, если на сервере было пусто).

- Если `rev` совпадает с текущей версией на сервере (или база пуста и `rev` равен `null`): сохранить `data`, выдать новую версию и ответить `200` `{ "rev": "18" }`.
- Если не совпадает — базу уже сохранил другой сотрудник: ответить `409` с текущей базой `{ "rev": "18", "data": { ... } }`. CRM сама объединит правки и отправит PUT ещё раз. Если два сотрудника изменили одну и ту же заявку или машину, останется вариант того, кто сохранил первым, а второй увидит предупреждение.

Проверка версии и запись должны быть одной операцией (транзакция или блокировка), иначе два одновременных PUT могут затереть друг друга.

Размер базы сейчас около 300 КБ, лимит тела запроса лучше поставить с запасом — от 10 МБ.

## Вход и права

- Всё — и сайт, и `/api/state` — должно открываться только после входа. В базе данные клиентов, оплаты и зарплаты.
- CRM отправляет запросы с cookie (`credentials: "include"`). Если сессии нет, отвечайте `401` или `403`: CRM покажет «Сервер просит войти заново» и ссылку на `loginUrl` из `js/config.js`.
- Если API на другом домене, нужен CORS с `Access-Control-Allow-Credentials: true` и точным `Access-Control-Allow-Origin` (не `*`). Проще держать сайт и API на одном домене.
- `js/data.js` — это данные из Excel в открытом виде. Когда база уже на сервере, соберите сайт без него: `python3 tools/build.py --api /api --no-seed`.

## Резервные копии

Сервер хранит одну текущую версию. Стоит сохранять и предыдущие (например, каждую версию или раз в день), чтобы можно было откатиться. Вручную копию можно скачать и восстановить в CRM: Настройки → «Резервная копия (JSON)» / «Восстановить из копии».

## Минимальная схема хранения

Одна таблица на одну строку:

```sql
CREATE TABLE crm_state (id INTEGER PRIMARY KEY CHECK (id = 1), rev INTEGER NOT NULL, data TEXT NOT NULL, updated_at TIMESTAMP);
-- PUT: UPDATE crm_state SET rev = rev + 1, data = :data, updated_at = now() WHERE id = 1 AND rev = :rev
--      ни одна строка не изменилась → 409; таблица пустая и rev = null → INSERT с rev = 1
```
